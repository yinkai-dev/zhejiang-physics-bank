# 数据与标签规范

本文件定义首版导出和筛选合同。`metadata/paper-catalog.json` 是已准备的卷级目录；题面静态 schema 和导出器由下一阶段实现。

## 1. 年份与考试分类是首版核心字段

用户已经按“25 二考／26 二考／27 首考”整理题库，保留该分类作为一级入口。**备考目标年份与实际考试年份分开存储和筛选。**

| 字段 | 含义与规则 |
| --- | --- |
| `paper_id` | 稳定卷 ID；首批采用 `collection_id--source_document_id`，改标题不改 ID |
| `collection_id` | 原题库分类：`zj-25-erkao / zj-26-erkao / zj-27-shoukao` |
| `original_classification` | 原有中文分类，保留用户组织方式 |
| `target_year` | 面向哪一届／哪一年选考备考；例如 2027 |
| `target_session` | 面向首考 `first`、二考 `second`；不能代替真实考试性质 |
| `exam_year` / `exam_month` | 试卷实际考试年／月；未知为 null |
| `exam_date` | 仅有原卷明确完整日期时填写 YYYY-MM-DD；不从年月补成 1 日 |
| `date_basis` | 日期证据；首批 `source_title_yymm` 表示从卷名 YYMM 推得，待源卷进一步核对 |
| `exam_kind` | `practice` 备考卷、`official` 正式真题；首批全部为 practice |
| `official_session` | 正式真题的实际首考／二考；备考卷为 null |
| `title` | 原卷标题，保留城市、学校、联盟、考试名称；显示简称可以另设 |
| `metadata_review_status` | 首批为 `classification_preserved_date_inferred`，说明原分类保留而日期来自卷名 |

首批真实示例：

```json
{
  "paper_id": "zj-27-shoukao--z20-lianmeng-2608",
  "collection_id": "zj-27-shoukao",
  "title": "物理卷-2608Z20联盟",
  "original_classification": "2027 首考",
  "target_year": 2027,
  "target_session": "first",
  "exam_year": 2026,
  "exam_month": 8,
  "exam_date": null,
  "date_basis": "source_title_yymm",
  "exam_kind": "practice",
  "official_session": null
}
```

页面建议显示“2027 首考备考 · 2026 年 8 月 · Z20 联盟”。“2027 首考”筛选应命中该卷；“实际考试年份 2027”不应命中。

年份从元数据生成可选项，添加新年份不应改页面源码。未知年月作为未知保留。正式真题后续入库时，考试年和阶段按源卷证据填，不从所属文件夹盲目推断。

## 2. 筛选与检索规则

- 不同筛选维度取交集；同一维度多选默认取并集。界面明确“备考年份”和“考试年份”的名称，不使用含义模糊的两个“年份”。
- 37 卷目录的目标年份分布：2025 = 11 卷／198 题，2026 = 21 卷／378 题，2027 = 5 卷／90 题。首考 = 5 卷／90 题，二考 = 32 卷／576 题。
- 当前目录实际考试年份：2025 = 11 卷，2026 = 26 卷；没有实际考试年份为 2027 的卷。该事实可作为年份混淆的验证用例。
- 首批 `exam_kind=official` 应为零。未来添加正式真题时与备考卷共用筛选，但保留清楚标识。
- 原有五大主题（力学、电学、光学、热学、近代物理）和题型沿用来源标签。一题多主题时按稳定题目 ID 去重，不能相加标签计数当总题数。
- 所有筛选和排序条件可以写入 URL；空结果不自动换年、换阶段或加题。命中列表分页／分批渲染，不能把前 300 条当完整总数。

## 3. 题面与答案的静态投影

来源是冻结 `question-package` 中的 `questions.jsonl`、资产清单和配图；标签、答案包分别关联。新站仅导出展示所需字段：

| 数据 | 导出要求 |
| --- | --- |
| 题目 ID | 使用全局唯一组合（collection_id + 原 question_id），保留原 ID 和原题号；原题号作为字符串处理 |
| 卷关系 | 绑定稳定 paper_id，继承卷级年份和考试分类；通过索引引用，避免手动复制年份到每题导致漂移 |
| 题干／选项 | 适配既有 `body` 与 `choices`，按真实块 schema 处理 text/math/figure/table；不得用检索摘要代替完整题面 |
| 配图 | 只复制被题干、选项、答案引用的必要资产；题目图和答案图均要建立映射，不复制整个来源目录 |
| 公式 | 保留原 LaTeX 含义，处理与浏览器渲染器的兼容；未知命令或复杂表格进入显式问题清单 |
| 主题／题型 | 沿用源标签；原题号、单多选、实验、计算保持可追溯 |
| 检索文字 | 从已审核来源生成，不要求网页浏览时调用模型 |
| 来源 | 展示原卷名称和原题号；保留公开可用的来源指纹，剥离本机绝对路径和运维身份 |
| 答案 | 仅取匹配题目指纹的已有答案 key/body；区分来源答案、明确缺失、尚未入库 |
| 解析 | 有来源则展示；答案与详解不是同一概念，只有答案字母时不能标为“完整解析” |

原题包字段严格受限且有哈希，不将新年份、精细标签或难度写回原包。新增注释单独保存，以题目 ID、来源指纹和标注版本绑定，在静态导出时合并。

建议产物为 `data/catalog.json`（卷目录）、`data/questions-index.json`（全量轻索引）、`data/papers/<paper_id>.json`（逐卷详情）及 `images/`。具体 schema 确定后固定版本，保持引用一致。

前端采用文本节点／受控渲染函数；题文中的内容不作为任意 HTML 或 JavaScript 执行。数学、表格、图片各由明确适配器处理。

## 4. 完整性与状态

- 原始三库共 666 题，原题号集合必须逐卷核对；导出题数不一致时阻止发布，并给出具体卷和题。
- 463 条状态为 `source` 的原卷答案全部应能按 ID 关联；2026 二考 5 条 `missing` 与 2025 二考 198 条未接答案包分别显示。
- 所有引用图片必须可解析、可定位，缺图不得跳过题目再宣称全量成功。
- 题目公共条件、同页共享图和选项中的公式图形一并检查。
- 现有浙江三库的题型标签有 18 题模板，但网站数据模型必须支持其他题数。未来正式真题不套用 18 题位置规则。
- 已完成的上游源内容检查可沿用；本项目重点验证转换、渲染、分类和打印。源码／数据发生变化时检查受影响范围。

## 5. 后续考点与难度

细分考点采用受控词表、稳定 ID、一题多标签；主考点、辅助考点、方法和情境分开。首版五类主题可用即可，不为凑完整树而随题创造标签。

难度首版允许为空，页面据实显示未标注或暂不显示筛选。后续可加入基础／中档／较难、判定理由、标注者和版本；真实学生正确率另存，不能当成同一数据。参考站的 11 维评分不作为首版必需项。

## 6. 本地和公开文件

`.local/banks/` 是来源快照，含原始文本、审核和导入信息；保留在本机。`metadata/paper-catalog.json` 是可公开的人工分类／卷名元数据。

用户已选择公开题库网站并允许以现有浙江三库开始。执行时按本文件的字段白名单生成公开题面、图片与已有答案，核对实际提交和 Pages 构建内容；不把这个授权扩展到其他题库、原始 PDF、凭据或无关材料。来源声明应区分原创网站代码、整理后的题目内容及第三方依赖。
