# 实施方案

决策日期：2026-11-09。项目名称：yinkai 的浙江高考物理题库。

## 1. 首版目标与范围

让用户打开网站后，可以按“哪一届、首考还是二考、哪张卷、哪类题”找到原题，查看已有答案，并勾选题目打印专项练习。

首版直接使用现有浙江三库，不等待新真题录入、精细考点和难度打分。旧讨论中“先三份真题、扩至 8–12 套”的建议已由本轮用户决定替换为“先利用现有题库搭第一版”。

| 现有分类 | 卷数 | 题数 | 原卷答案情况 |
| --- | ---: | ---: | --- |
| 2025 二考 | 11 | 198 | 尚未接入答案包 |
| 2026 二考 | 21 | 378 | 373 题有来源答案，5 题明确缺失 |
| 2027 首考 | 5 | 90 | 90 题有来源答案 |
| 合计 | 37 | 666 | 463 题有来源答案 |

这是本机快照盘点；有来源答案不等于每题都附完整详解。37 卷均归备考卷，不能在宣传或页面标题中标成 37 套高考正式真题。强基库暂不纳入主站。

## 2. 用户入口和页面

### 题库首页

- 网站名及三类备考入口：2027 首考、2026 二考、2025 二考，按目标年份降序排列。
- 首屏展示可组合筛选：**备考年份、首考／二考、试卷类型、题型、主题、是否有答案**。实际考试年月作为次级筛选及排序。
- 搜索原卷名称、学校／地区／联盟关键词及题目检索文字。首版为关键词匹配，不标为语义理解。
- 命中数按唯一题目计算；筛选交集为空时明确显示，无跨库自动放宽条件。
- 试卷卡片显示完整卷名、备考分类、实际考试年月（已知时）、题数及答案覆盖。

### 试卷页与单题页

- 保留原卷标题、原题号、单选／多选／实验／计算等信息。
- 正确展示文字、公式、选项、必要题图、表格和共享条件；支持手机宽度。
- 单题有稳定链接，可前后切题、加入练习清单。
- 答案默认折叠。有原卷答案就展示；无答案显示状态。来源没有解析时不生成假解析。
- “面向 2027 首考的 2026 年 8 月联考卷”应同时展示两个时间维度，不能显示成“2027 年已举行的考试”。

### 练习清单与打印页

- 跨卷添加、去重、移除、调序、清空；清单保存在当前浏览器。
- 每题打印原卷来源与原题号；可选择只打印题目或包含已有答案。
- 首版使用浏览器打印／另存 PDF。文字和公式保留可读排版，复杂长题可合理分页，关键图表不能被截断。
- 收藏和清单不承诺跨设备同步。后续服务端精排可接既有 MCP，但不是首版依赖。

## 3. 技术选择

- **GitHub 仓库 + GitHub Pages**，项目站点路径预计为 `/zhejiang-physics-bank/`。
- 前端建议 Vite + TypeScript + 原生页面；初期使用轻量多页结构 `index.html / paper.html / question.html / worksheet.html`，通过查询参数定位题目，刷新不依赖服务器路由。
- 公式优先 MathJax，依赖作为本站静态资源打包，减少关键渲染对外部 CDN 的依赖。确认第三方许可证和所用 TeX 命令兼容性。
- 索引和详情分离：先加载轻索引，在浏览器筛选后按需读取逐卷 JSON；图片懒加载。JSON 不需要在线数据库。
- 导出工具可使用 Node.js；需要既有 Python 适配时按 64 位约定配置。保留已有题包，不重写上游系统。
- 确定依赖版本后提交锁文件，验证生产构建及 Pages 子路径；本轮未安装前端依赖，以下命令与目录属于实施目标。

```mermaid
flowchart LR
    A[本机既有题包与答案包] --> B[白名单静态导出]
    C[试卷年份与考试分类] --> B
    B --> D[轻索引、逐卷题面与必要图片]
    D --> E[GitHub Pages 静态网站]
    E --> F[浏览、筛选、选题与打印]
```

建议目录：

```text
docs/                   方案、规范和执行记录
metadata/               可公开的卷级分类，首批目录已生成
scripts/                数据准备、导出和发布前检查
src/                    页面与静态检索逻辑（待实现）
public/                 可发布网页资源（待实现）
public/data/            白名单题面及索引（待导出）
public/images/          必要题图及答案图（待导出）
.github/workflows/      生产构建与 Pages 部署（待实现）
.local/banks/           本机原始快照，Git 忽略
.local/evidence/        校验和页面检查证据，Git 忽略
dist/                   构建输出，Git 忽略
```

`public/data/` 和 `public/images/` 当前被忽略，防止执行者误把整个原始包当成静态数据提交。完成字段白名单、来源和资产检查后，将实际允许发布的导出物改为跟踪文件，使 GitHub Actions 仅凭公开仓库即可构建站点；不要依赖 Actions 读取开发电脑的 `.local/`。

本机工具、环境、缓存和日志均落在本项目内，开发预览只绑定回环地址；这不会新增需长期运维的线上服务。首次开发前选择空闲端口并记录。

## 4. 第一版与后续优化

首版必需：三库全量展示、年份与阶段筛选、原题号和题型、五大主题、已有答案、跨卷清单、打印、可分享链接、手机可用。

首版允许：精细考点为空、难度为空、无来源答案明确缺失、实际日期只精确到年月。这些缺失不能通过臆测填齐。

第二阶段：受控细分知识点及同义词、主考点／辅助考点、三档预估难度及依据、题目勘误、逐步补齐原卷答案。

第三阶段：经审核的历年正式真题；根据真实需求接入 MCP 精排出卷、账号收藏同步或问答。避免同时重建 DeepTutor、会员、在线 OCR、向量库和完整后台。
